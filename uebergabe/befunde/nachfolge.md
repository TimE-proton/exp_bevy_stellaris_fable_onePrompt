# Prüfung von Besitzwechsel, Nachfolge und Enden (geprüfter Stand 816d69c)

## Blickwinkel „erhaltung“

Die Gegenprüfung dieses Blickwinkels hat nicht stattgefunden: Alle Befunde gelten als offen und ungeprüft.

### 1. Saves written before this change are still accepted (SAVE_FORMAT stays 4) and panic at the first change of owner

- Urteil: **ungeprüft**
- Schwere laut Prüfer: major
- Ort: `crates/sim/src/state.rs:180`

**Beschreibung.** The change adds state that is indexed without bounds checks (Endgame.path / absorbed_pop / gap / seat per planet, Diplomacy.standing / culture per community) but leaves SAVE_FORMAT at 4. A format-4 save from the previous program version deserializes through #[serde(default)] with EMPTY lists, and SimState::install (state.rs:49-54) only syncs the Economy lists. The implementer listed 'SAVE_FORMAT must be raised by the integrator' and expected only a failing succession::check; in fact the simulation panics. M6_Synthese section 2 (a named source of this package) ties the format bump to exactly this state change, and the project's own convention (comment at fleet/mod.rs:230, tests in fleet/mod.rs:1075 and tests/military.rs:1629) is that older layouts are recognised by the format number and rejected. crates/game loads a save whose data hash differs with only a warning (crates/game/src/session.rs:117-131), so the format number is the only guard.

**Fehlerbild.** Observed. A save written by the binary built from 5ac904d ('headless_base run --data-dir data_base --seed 3 --years 8 --save alt_format4.ron') is read by the new code with SaveGame::read -> Ok, format 4. After Headless::from_save: Endgame.path has 0 entries, Diplomacy.standing 0, check_invariants returns 'Liste je Gemeinschaft (Stellungen) hat 0 Einträge bei 6 Gemeinschaften'. Then apply_secession on a colony (exactly what the monthly cohesion system does) panics: 'index out of bounds: the len is 0 but the index is 18' at crates/sim/src/endgame.rs:177 (Endgame::tag, called from polity/succession.rs:554). Derived from the code: the same panic in Endgame::clear_planet (endgame.rs:197) as soon as the migration system abandons a colony (galaxy/plugin.rs:59), and at diplomacy.standing[..] in conclude (polity/succession.rs:951) and subordinate (:1074). A peaceful 60-year AI run of the loaded save did not crash only because it contained no secession and no abandoned colony. Reproduction material: /tmp/claude-0/-home-user-exp-bevy-stellaris-fable-onePrompt/3f2a4996-068c-56f0-93b7-939afbb9e098/scratchpad/nachfolge/pruefung/alt_format4.ron and test 'alter_spielstand' in /tmp/claude-0/-home-user-exp-bevy-stellaris-fable-onePrompt/3f2a4996-068c-56f0-93b7-939afbb9e098/scratchpad/nachfolge/pruefung/tmp_pruefung.rs (copy to crates/sim/tests, run with PRUEF_SAVE=<path> PRUEF_MODE=sezession).

**Vorschlag.** Raise SAVE_FORMAT to 5 in this change (one line plus the 'Format 5: ...' comment), so SaveGame::from_ron rejects older saves the same way it rejects formats 1-3; the existing tests iterate 1..SAVE_FORMAT and keep passing. Alternatively size the new lists in SimState::install, but the format bump is what the sources and the project convention ask for.

### 2. DistributeShares can hand shares to the state of a community that has ended

- Urteil: **ungeprüft**
- Schwere laut Prüfer: minor
- Ort: `crates/sim/src/command.rs:408`

**Beschreibung.** command::execute rejects commands OF ended communities (line 310), but the receiver 'to: HolderId' of DistributeShares is passed unchecked to finance::distribute_shares (finance/shares.rs:236). A living community can therefore make State(ended) a holder again. That breaks three items of design F at once (an ended community holds no shares as a state, has no treasury, nothing in the state refers to it) and takes money out of circulation: pay_dividend credits the treasury of the ended community, and nothing ever spends it (settle_public_accounts skips communities without population, economy/capital.rs:400-405). money_drift stays 0, so only succession::check notices. This is the one place found where a command of a living community can name an ended one; DeclareWar / MakePeace are covered by check_pair.

**Fehlerbild.** Observed (seed 16, 6 years, then absorb(G1, G2, Forced)): G3 issues DistributeShares { issuer: Kontor(S17), shares: 50, to: HolderId::State(G1) } -> outcome Applied. In the same month-start tick the treasury of the ended community is 272806 (272.8 credits) and check_invariants returns 'Orden der Tiefen Uhr hat geendet, hält aber eine Staatskasse'; with an issuer that pays no dividend that month the message is '...: Anteile bei State(PolityId(1)), einem Staat, der geendet hat'. The UI and the AI only send Public(planet) receivers, so today this needs a script, a replayed log or a later caller (for example the planned share swaps between states). Reproduction: tests 'befehl_nennt_beendeten_staat' and 'befehl_nennt_beendeten_staat_dividende' in /tmp/claude-0/-home-user-exp-bevy-stellaris-fable-onePrompt/3f2a4996-068c-56f0-93b7-939afbb9e098/scratchpad/nachfolge/pruefung/tmp_pruefung.rs.

**Vorschlag.** Validate the receiver in command::execute before calling distribute_shares: State(p) must be a living community, Elite/Public(planet) a known planet; otherwise return a German reason such as 'Empfänger besteht nicht mehr'. That also closes the older hole that an unknown planet index as receiver panics at the next dividend.

### 3. Forced end in a running battle: fighters without a carrier are booked as lost on the heir after all

- Urteil: **ungeprüft**
- Schwere laut Prüfer: minor
- Ort: `crates/sim/src/fleet/succession.rs:198`

**Beschreibung.** leave_field marks every ship of the dissolved side that is in play as Escaped and takes lost_value out of the side's books (the fix of commit d773925). Fighters of that side whose carrier was destroyed earlier stay in the calculator as escaped craft. When the battle ends, Battle::settle_fighters (battle/mod.rs:962) finds no hangar room for them, sets them Destroyed and adds them to lost[Fighter] and lost_value of the side, which relabel_combatants (line 191) has meanwhile assigned to the heir. fleet/battles.rs:780 and :868 then add that value to the heir's losses: its war weariness rises, the value is added to the debris, and with a small navy of the heir the heavy-defeat price shock (battles.rs:871) can fire. So the heir is still charged with losses of the ended community, for the part of the loss that is only booked after the dissolution.

**Fehlerbild.** Observed (seed 5): community G1 gets two carriers 'horst' and fights G0 in its home system; once at least 4 of its fighters are in the air the carriers are destroyed; then absorb(G1, G2, Path::Forced), G2 uninvolved and at peace. The battle is called off; the report side of the dissolved fleet shows owner G2, lost [4, 0, 0, 0, 0, 0], lost_value 428; war weariness of G2 goes 0 -> 0.619, debris in the system 0 -> 428. Control run without the destroyed carriers: lost_value 0, weariness of G2 stays 0. The implementer's test dissolved_fleets_leave_the_field_the_road_and_the_yard has no fighters in the air and therefore passes. Reproduction: test 'verwaiste_bordjaeger' in /tmp/claude-0/-home-user-exp-bevy-stellaris-fable-onePrompt/3f2a4996-068c-56f0-93b7-939afbb9e098/scratchpad/nachfolge/pruefung/tmp_pruefung.rs.

**Vorschlag.** In leave_field take the fighters of the side (source None, class Fighter) off the field as Destroyed without booking them, instead of Escaped, so that settle_fighters has nothing left to book; or, when a battle concludes, ignore lost_value of a side whose fleet no longer exists. Add a carrier case to the unit test.

### 4. Peaceful end in a running battle: losses from before the union raise the heir's war weariness and are counted as the heir's lost ships

- Urteil: **ungeprüft**
- Schwere laut Prüfer: minor
- Ort: `crates/sim/src/fleet/succession.rs:150`

**Beschreibung.** pass_fleets relabels the battle side of a handed-over fleet to the heir together with everything that side has lost so far (lost, lost_value). When the battle concludes, fleet/battles.rs:780 charges the whole lost_value to the heir (war weariness at :868, possibly the heavy-defeat shock at :871 if none of its sides holds the field), and battles.rs:798 adds the ships the ended community lost before the union to ships_lost of the heir, while the counter of the ended community stays untouched. On the forced path the implementer treats exactly this as a defect ('the heir is not charged with it', decision 14); on the peaceful path the same accounting remains and is neither documented nor tested (assert_aftermath in tests/military.rs does not look at weariness or ships_lost). It also means that any later war score fed from the battle sides would credit the heir with losses from a war it was not part of.

**Fehlerbild.** Observed (seed 5): G0 with six extra cruisers attacks G1 at home; after G1 has lost one corvette (lost_value 1672 on its side) absorb(G1, G2, Path::Joined), G2 at peace with everybody. The battle is called off; the side is reported with owner G2 and lost_value 1672; war weariness of G2 goes 0 -> 1.209 although G2 never was at war, ships_lost_by(G2) goes 0 -> 1 and ships_lost_by(G1) stays 0 (so the per-community ships_lost column of the sweep CSV attributes the ship to the wrong community). Reproduction: test 'friedliches_ende_nach_verlusten' in /tmp/claude-0/-home-user-exp-bevy-stellaris-fable-onePrompt/3f2a4996-068c-56f0-93b7-939afbb9e098/scratchpad/nachfolge/pruefung/tmp_pruefung.rs. Review note for the record: apart from the four findings the hard cases held. Tested without finding: capital falls while the loser's fleet is in battle and a second one in transit (24 months, run_days equals run_days_exact); all planets of a community transferred on one tick (forced and joined, with bonds on both sides); founding from a capital that keeps colonies; heir is overlord / ward of the one that ends; a head conquered while it has wards; a ward's last planet going to another ward; a broad random sequence of transfers (all paths and receivers), foundings, ends, subordinations, secessions and commands on 200 seeds with up to 100 steps each, checking money, share totals, population, check_invariants and save/load after every step, 10 of them against an exact-tick twin: no violation. All items of design F have a checking line in succession::check. cargo test -p sim: 297 passed, 1 ignored; the scripted-war sweep on seeds 20..24 equals the 5ac904d baseline in the 20 common columns. Nothing here comes from stored memory.

**Vorschlag.** Decide and document. Either close the books of the side at the handover as on the forced path (move lost_value so far into the debris, count the ships already lost on the ended community, start the side at zero for the heir), or state in the doc comment of pass_fleets and in a test that the heir deliberately takes over the fleet with its losses.
